# M5.1 governance workflow semantics

`check-governance.yml` is intentionally observational. It uses read-only repository permissions and fails when live GitHub state shows `main` is unprotected and no active ruleset applies to `main`.

A failing governance workflow is therefore expected until repository administration is changed. M5.1 must not make this workflow a required code-CI check before that administrative change, because doing so would permanently block the repair PR. The formal v0.1.1 publication gate includes governance PASS separately.
